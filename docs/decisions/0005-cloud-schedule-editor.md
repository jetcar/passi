# ADR-0005: редактор локальных расписаний в Passi

Дата: 2026-11-24. Статус: принято для реализации, не развёрнуто.

## Контекст

Локальный сервер имеет недельные расписания розеток и ручной приоритет. Требуется
управлять ими через Passi, сохранив работу дома при недоступности облака.
Действующие агенты понимают только Exchange и power.set; без согласования новый
тип команды нарушил бы их протокол. Resume по одной версии конфигурации не защищает
от снятия более новой ручной паузы после потери ответа.

## Решение

Добавить отдельный ExchangeSchedule версии 1 для одного устройства, с теми же
аутентификацией, соединением и homeId. Свежий снимок этого метода служит явным
объявлением поддержки. Существующий Exchange не передаёт команды расписаний.
Снимки и журнал команд хранятся в существующем PostgreSQL; облако не исполняет таймеры.

Запись выполняется локально атомарно с expectedVersion и устойчивым журналом commandId.
Resume дополнительно проверяет expectedRuntimeRevision. Локальная revision увеличивается
при каждом изменении ручного режима, включая ручную команду, которая повторяет текущее
состояние. Обе версии и журнал должны сохраняться под одной блокировкой планировщика.

После доставки команды облако не отправляет её повторно. Потерянный результат остаётся
unknown, а интерфейс загружает текущий снимок. Новая запись требует явного действия;
изменение версии не приводит к автоматической перезаписи черновиком.

## Альтернативы

- Облачный таймер: отвергнут, поскольку отсутствие WAN остановило бы расписание.
- Расширение v1 Exchange новыми командами для всех агентов: отвергнуто из-за несовместимости.
- Resume только по версии конфигурации: отвергнут, ручное действие не меняет эту версию.
- Произвольный прокси к локальному API: отвергнут, транспорт допускает лишь известные операции.

## Последствия

Старые агенты сохраняют ручное управление, но не получают редактор расписания.
Перед фактическим облачным редактированием необходим отдельный выпуск локального адаптера
по [контракту](../smart-home-schedule-agent-contract.md). Этот PR локальный проект не меняет.
Сохранённые настройки не означают подтверждённое переключение устройства.
Термостатное расписание — отдельный будущий протокол, не выдаваемый за подключённый.
