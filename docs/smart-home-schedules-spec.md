# Расписания в Passi

## Объём и границы

Управление недельными расписаниями питания розеток, уже зарегистрированных своим
домашним агентом. Источник истины и единственный исполнитель — локальный сервер.
Облако не выполняет расписание и не воспроизводит пропущенные переключения.
Существующие вход, владелец, CSRF BFF, токены агентов и power.set сохраняются.
Работа только в Passi; локальный проект читается для совместимости, но не изменяется.
Тесты используют эмулятор; production и реальные устройства не изменяются.
Термостаты и другие типы расписаний не изображаются поддерживаемыми этим протоколом.

## Контракт расширения

Существующий SignalR Exchange остаётся v1 и передаёт только power.set. Новый
ExchangeSchedule принимает снимок одного устройства и означает явное объявление
поддержки протокола расписаний версии 1 именно этим агентом/устройством. Агент без
этого метода не получает новые операции. Максимальный размер сообщения — 64 KiB.

Вход: protocolVersion=1, deviceId, snapshotAt, configuration, runtime, results[].
configuration: version (0..9007199254740991), deviceId, enabled, timeZone,
outsidePower (bool|null), intervals (до 64): id UUID, name до 80, enabled, days
(уникальные ISO 1..7), start HH:mm, end HH:mm (допустимо 24:00), on bool.
Конец раньше начала переносится на следующий день; равные start/end запрещены.
24:00 допустимо только в end. При максимальной безопасной версии операция,
требующая её увеличения, отклоняется.
Противоречивые пересечения активных интервалов запрещены, включая переход воскресенья.
timeZone — существующий IANA timezone. Никаких IP, ключей, скриптов или HTTP-адресов.

runtime: revision (0..9007199254740991), state, desiredPower?, actualPower?, checkedAt?,
nextCheckAt?, nextBoundary?, manualActive, manualUntil?, error?. revision сохраняется
локально и увеличивается при любом изменении ручного режима, включая повторную ручную
команду. Это защищает resume от снятия более новой ручной паузы.

results: до 1 результата {commandId, status:confirmed|failed|unknown, observedAt?,
appliedVersion?, runtimeRevision?, errorCode?}. Выход: serverTime и commands[], не
более одной команды для этого устройства. CommandDto расширяется expectedVersion?,
expectedRuntimeRevision?, configuration? и operation=schedule.replace|schedule.resume.
On остаётся совместимым с power.set, расписание его не использует.

Сохранение: уникальный commandId; expectedVersion и configuration.version равны
прочитанной версии. Локальный агент применяет CAS, атомарно сохраняет конфигурацию и журнал ID,
увеличивает version ровно на 1. Resume: commandId, expectedVersion,
expectedRuntimeRevision; локальный агент проверяет обе версии, снимает ручную паузу,
увеличивает runtime.revision ровно на 1 и сохраняет журнал ID. Повтор ID с тем же
намерением возвращает прежний результат, с другим — конфликт. После потери ответа
повторное выполнение запрещено; сначала новый снимок и явное действие пользователя.

Облачная очередь использует существующий журнал команд, фиксированный срок 30 секунд,
fencing соединения, изоляцию (homeId,deviceId), одно активное действие на устройство.
Подтверждение проверяется по свежему снимку того же устройства, версии, содержимому,
revision и observedAt>=sentAt. Подтверждение означает сохранение/снятие паузы,
но не переключение физического устройства. Terminal unknown не становится confirmed.
Power и schedule обмены никогда не доставляют команды другого семейства.

Dashboard HomeDto.schedules: [{deviceId,snapshotAt,stale,configuration,runtime}].
Кэш сохраняется, но при обрыве, новом соединении или отсутствии свежего снимка
показывается устаревшим. Старая версия/время и изменение содержимого без новой версии
отклоняются. Исчезнувшее из inventory устройство не может получать расписания.
История версий сохраняется при исчезновении/повторном добавлении ID. На дом допускается
до 128 исторических снимков устройств; новый ID сверх лимита получает schedule_cache_limit.

HTTP owner/BFF: POST homes/{homeId}/devices/{deviceId}/schedule с
{commandId,expectedVersion,configuration}; POST .../schedule/resume с
{commandId,expectedVersion,expectedRuntimeRevision}. Все права и CSRF прежние.
Конфликт версии требует загрузки текущего снимка, без автоматической перезаписи.

## Интерфейс

Редактор на карточке устройства: включение расписания, часовой пояс, поведение вне
интервалов, дни/время/включение или выключение интервала; добавить/убрать строку в
черновике, сохранить, вернуть текущий снимок. Черновики в памяти по (homeId,deviceId),
polling их не перезаписывает. При конфликте сохраняется черновик и показывается новая
версия. Старый агент: «Для расписания требуется обновление локального агента».
Отдельные статусы отправки и сохранения; ручной режим и «Возобновить»; offline/stale
блокирует отправку, но оставляет последние данные с временем.

## Проверки и команды

NUnit/PostgreSQL: совместимость v1, чужой владелец/дом, неверный deviceId,
протокол, валидация интервалов/часового пояса, CAS и runtime revision, подтверждение,
дедупликация, обрыв/таймаут, stale, отсутствие повторного снятия ручного режима.
BFF: фиксированные маршруты, CSRF, отсутствие повтора. UI: черновик при polling,
сохранение/конфликт/устаревание/разделение серверов. Браузерный эмулятор без устройств.

Сборка/тесты: `rtk dotnet test PassiWebApiTests/PassiWebApiTests.csproj -v quiet`;
`rtk dotnet test WebAppTests/WebAppTests.csproj -v quiet` (последовательно);
в WebApp/vue-project: `rtk npm run type-check`, `rtk node --test src/smarthome/__tests__/*.test.mjs`,
`rtk npm run build-only -- --outDir <temporary-directory>`.
Изменения C# следуют существующим DTO и SmartHomeService/Atomic; UI Vue3/Bootstrap.
