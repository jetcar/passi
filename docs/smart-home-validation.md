## Браузерный эмулятор

Проверен отдельный loopback-эмулятор, без подключения локального домашнего проекта:

- Исходное «Выключено»; после POST статус sent, фактическое состояние не меняется, кнопки отключены.
- После эмулированного обратного чтения — «Включено» и confirmed.
- API 502 сохраняет последние данные с пометкой устаревания и блокирует управление.
- Старые timestamps дают offline/stale; 403 убирает данные и пункт меню.
- Зарегистрирован ровно один POST, без автоматических повторов.
- Временный сервер и вкладка закрыты.

## Независимая проверка и ограничения

Отдельное ревью нашло несовпадение HTTPS boundary с HTTP hop HAProxy → WebAPI.
Исправлено узкой обработкой forwarded headers только от точных адресов доверенного прокси для SmartHome.
Проверены HTTP hop с JWT, регистрацией и WebSocket, запрет чужого прокси, поддельной цепочки заголовков,
незащищённого протокола, ошибочной конфигурации и DNS failure. Лимиты регистрации раздельны для
клиентов за доверенным прокси; поддельный префикс X-Forwarded-For не меняет идентичность клиента.
Остальные маршруты не меняются.

Существующие зависимости System.Security.Cryptography.Pkcs/Xml 10.0.12 дают NuGet security warnings.
Они не обновлялись в рамках этой задачи. Новые тестовые SignalR.Client/TestHost используют 10.0.13,
после обновления с 10.0.12 предупреждение SignalR.Common для них устранено.

Реальный production GUID и вход после выпуска не проверялись: привязка выполняется серверным поиском
существующей подтверждённой учётной записи при первом разрешённом запросе, а не переданным из UI GUID.
Нельзя считать эту сессию production smoke test. Локальный агент ещё должен быть реализован по
[готовому контракту](smart-home-agent-contract.md) и пройти собственные проверки эмулятором.
